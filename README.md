# 万象图谱 · WanxiangAtlas

> **时空叙事可视化系统** · Spatiotemporal Narrative Visualization
> 把叙事抽象成维度关系图谱，梳理时间与空间，AI 生成环境，3D 漫游呈现，因果推演预测。

---

## 系统简介

万象图谱（WanxiangAtlas）是一套时空叙事可视化系统：把叙事中的维度关系抽象成知识图谱，梳理时间线与空间线，由 AI 生成环境，以 3D 漫游呈现并支持因果推演。它回答一个核心问题——**任何会变化的东西，该盯哪些量、这些量怎么变、变与变之间谁因谁果。**

> **备注（举例）**：已验证的叙事题材如《西游记》《完美世界》《凡人修仙传》《斗罗大陆》；规模实测为 160 场景 → 1292 槽位 → 1282 维度实例 → 49 类型。

---

## 一、维度是什么

**维度 = 按时间、地点、人物、事件等变化的信息。** 任何一条维度都由四件事构成，缺一件就不算维度：

```
D = ⟨ Sub, Ax, Val, Δ ⟩ + Anchor
    主体  变化轴  值域  演变算子   锚(主体id, 坐标)
```

| 项 | 名称 | 含义 |
|---|---|---|
| `Sub` | **主体** | 这条信息讲的是「谁的」 |
| `Ax` | **变化轴** | 沿什么坐标被观察 |
| `Val` | **值域** | 取值是什么形态 |
| `Δ` | **演变算子** | 值是怎么变的 |
| `Anchor` | **锚** | 能挂到 `(主体id, 坐标)` 上 |

> **锚是最容易被跳过、也最关键的一项**：没有锚，维度之间无法建立唯一联系，不同场景里的同名量就会互相覆盖。

> **备注（举例）**：典型的维度如功法升级链、法宝升级链、人物关系事件变化链。反例（不是维度）：「流动性」缺主体、「宏观环境」缺变化轴、「发展得好不好」缺值域、「综合实力」缺算子、「行业景气度」缺锚——不指明哪个主体、哪个坐标，就没法算。

## 二、六条变化轴

| 轴 | 名称 | 问什么 |
|---|---|---|
| `T` | 时间轴 | 什么时候 / 变成什么了 |
| `S` | 空间轴 | 在哪里 / 怎么扩散 |
| `P` | 人物轴 | 谁与谁（关系类，至少两个锚点） |
| `E` | 事件轴 | 第几件事 |
| `L` | 层级轴 | 在第几层 |
| `R` | 规则轴 | 允许做什么 |

> **事件轴为什么单列**：事件序（第几件事）与时间跨度（走了多久）是两个不同坐标，混用会把「进度」和「历时」搅在一起。凡是有里程碑、阶段、分期口径的场景，事件轴都压过时间轴。

> **备注（举例）**：空间轴如疆域、感染扩散、产业转移、航道；事件轴如八十一难序、通关阶段、战役序；层级轴如境界、职级、位面；规则轴如立法、门规、货币政策框架。「取经十四年」是时间跨度，「八十一难」是事件序，二者不可换算。

## 三、七种演变算子

| 算子 | 名称 | 判据 / 写作纪律 |
|---|---|---|
| `progression` | **升级链** | 序数阶单向递进，有门槛，可卡住。**必须说清升级条件** |
| `relation` | **关系迁移** | 有限状态间迁移，**每次迁移必须挂到某条事件边上** |
| `fluctuation` | 波动 | 谈「趋势」必须给窗口，不给窗口的趋势就是噪声 |
| `accumulation` | 累积 | **必须区分存量与流量**，混用是最常见的口径错误 |
| `phase` | 相变 | **必须标出阈值与滞回区间**，否则判不出「现在是哪一态」 |
| `migration` | 空间迁移 | 区分「主体移动」和「边界移动」，两者常同时发生但不是一回事 |
| `rule` | 规则变更 | **必须留版本号与生效时点**，否则历史无法回溯比较 |

> **备注（举例）**：升级链如功法链、法宝链、境界链；关系迁移如人物关系事件变化链、阵营归属链；波动如价格、热度、情绪、支持率；累积如修为总量、财富、库存、功德；相变如和平→战争、牛市→熊市、正常→危机；空间迁移如人界→灵界、产业转移、人口迁徙；规则变更如立法、门规、货币框架、协议版本。

## 四、九种值域

`num` 数值 ｜ `ratio` 比率 ｜ `ordinal` 序数阶 ｜ `enum` 枚举态 ｜ `bool` 布尔 ｜ `set` 集合 ｜ `seq` 序列 ｜ `graph` 图谱 ｜ `dist` 分布

值域决定了**能算什么**：`ordinal` 只能算位次和跃迁次数，取平均没有意义；`graph` 只能算中心度和连通性；`dist` 只能算熵和散度。没有这一层，就没法回答「这条维度能不能求导」。

---

## 五、值域 × 算子：一张必须遵守的表

任何算子都能配任何值域——这是错的。集合没有内在阶序，类别没有高低；值域与算子的搭配错误写在散文里拦不住，只能变成可执行的契约。

| 值域 \ 算子 | progression | relation | fluctuation | accumulation | phase | migration | rule |
|---|---|---|---|---|---|---|---|
| `num` 实数 | △ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `ratio` 比率 | △ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `ordinal` 序位 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `enum` 无序类别 | ✗ | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ |
| `bool` 二值 | ✗ | ✓ | ✗ | ✗ | ✓ | ✗ | ✓ |
| `set` 集合 | ✗ | ✓ | ✗ | ✓ | ✗ | ✓ | ✓ |
| `seq` 有序序列 | ✗ | ✓ | ✗ | ✓ | ✓ | ✓ | ✓ |
| `graph` 图 / 网络 | ✗ | ✓ | ✗ | ✓ | ✗ | ✓ | ✓ |
| `dist` 分布 / 向量 | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

`✓` 合法 ｜ `△` 有条件（必须给出台阶：门槛 / 档位 / 代际 / 分档）｜ `✗` 类型错误。
`relation` 与 `rule` 不受值域限制——它们是**主体形态**约束（至少两个实体 / 变化来自系统外部），任何值域都能承载关系强度或换口径。

**两条最容易踩的边界**：

1. `set` 只能配 `accumulation` / `relation` / `migration` / `rule`。集合的增减是累积，成员归属变化是关系迁移，**永远不是升级链**。
2. `seq` 虽然有序，但它的顺序是**过程顺序**不是等级阶梯。沿序列往前走是 `phase`，不是 `progression`。有序 ≠ 可登阶。

> **备注（举例）**：「会哪几门功法」是集合增减，不是「升了几级」；「诉讼阶段」（立案→侦查→起诉→一审→二审→执行）是有序台阶，值域写成无序类别再配升级链就是类型错误。

## 六、三层结构：场景 / 实例 / 类型

```
第 3 层  场景        ← 维度在这里诞生：这个场景真的要盯什么
            ↓ 枚举
第 2 层  维度实例    ← 具体可算：一个个可测量、可定位的量
            ↓ 抽象
第 1 层  维度类型    ← 跨场景可复用：同一类量的共同形态
```

- **数量是枚举的结果，不是乘法的结果**：每条维度都能反查到一个真实问题，没有出处就没有维护价值。
- 把分析视角当成维度、用乘法填格子，会产出大量永远用不到、无法反查的组合——这是被取代的旧做法。

> **备注（举例）**：实例如黄金价格、螺纹钢价格、批价、运价；类型如价格水平、位阶与等级、关系状态。规模实测：160 场景 → 1282 实例 → 49 类型。

## 七、语义契约

「值域和算子怎么搭」「两个名字算不算同一条」不能只写在散文里。契约是唯一「人写又受机器审」的真源——它不描述数据，它规定数据能长成什么样；五类规则由机器自动校验，任何硬违规都会被拦截。

| 规则 | 查什么 |
|---|---|
| **A1** | 值域 × 算子非法 |
| **A2** | 同属性跨主体签名冲突（同名量两种算子） |
| **A3** | 概念登记不完备（纯措辞重复 / 同概念不同主体） |
| **A4** | 修复被回退（已执行的裁决被改回去就报错） |
| **A5** | 契约自身不自洽（引用不存在的算子 / 维度即失败） |

**三类「像同一条」的关系**（同概念在两个场景被写成两条维度是常态，但常态不等于都对）：

| 类型 | 判据 | 处置 |
|---|---|---|
| **alias** 合并 | 同主体 + 同值域 + 同算子 + 措辞互为包含 | **必须合并**，保留措辞更完整的那条 |
| **scope** 分域 | 同概念、不同主体（主体来自各场景自己的实体表） | 两条都留，登记备案，**禁止跨主体直接比较** |
| **dual** 对偶 | 同一事实的两个查询方向，主体互为反 | 两条都留，登记备案，并声明**对账约束** |

> **备注（举例）**：对偶如持有关系——「A 持有哪些东西」（主体的属性，`set`）与「某物在谁手上」（物的属性，`enum`）是同一批事实的两个方向，必须共享同一次变化：一侧集合 +1 的累积，就是另一侧持有者迁移的关系变更，两侧条目数还必须能对账。**这不是重复，是互补；不登记，它看起来就是两条互相矛盾的维度。**

## 八、注意事项（写作纪律）

- **不伪造精度**：原文只给序数锚点就只用序数，只给量级就只标量级、不做算术。时间轴不能画成一根等距直线。
- **可序性 / 可比性显式声明**：层级是否可排序、量与量是否可比，都必须显式声明。原文没有排出高低，系统就只能回答「谁和谁发生过作用、结果如何」，不能回答「差多少」——任何画出「层级差数值」的可视化都是在编。
- **多题材通用**：时间坐标、层级栈、实体生命周期、约束、篇章簇、因果窗口、成本模型全部由配置驱动，不写死在逻辑里。判据很硬——**换一个题材，核心逻辑零改动**。
- **一个概念只有一处定义**：文档只引用，不复制；复制必然分叉。

> **备注（举例）**：
> - 不伪造精度——原文只给「贞观十三年出发」「取经十四年」两个锚点，硬算「第 3 年第 47 天」是伪造精度；跨度 300 万年而原文只说「数十万年过去」，就只标量级。
> - 可比性——原文从未把太乙金仙与大罗金仙排出高低，任何「境界差数值」都是编的。
> - 多题材通用——四本真书实测：因果窗口差 266.7 倍、时间跨度差 214,286 倍、段数差 8.5 倍、层级总数差 3.4 倍，任何一个是常量就会在另外三本书上错。
